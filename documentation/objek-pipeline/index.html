From a photo or a shop link to a 3D object you can spin in the browser

The generic version of the Cospace clothing experiment: any object in, a clean, correctly sized 3D model out, viewable on the web and ready for the Game Kit. Seven steps, each pinned to a fleet machine, with GPT-6 Astra as the Blender operator and a second model as the judge.

Short version
  1. What failed beforeThe Cospace attempt did not fail at "image to 3D". It failed at clothing on a body: rig mismatch, sleeves, T-pose, and fitting a garment to a torso. Tops actually worked by July. Generic objects skip all of that.
  2. CalibrationLast time "calibration" meant fitting a garment to a body by hand-tuned numbers. This time it means real-world size, taken from the product listing or confirmed by you before anything is generated, and checked automatically after.
  3. Which machinetr-home is the worker for version 1: official Blender, a 24 GB GPU for renders, the browser that can open Shopee, and Codex with Astra already logged in. bandung-01 is the NVIDIA box: normal chip plus a CUDA card with the AI libraries already installed, idle for seven weeks, so it becomes the phase 2 home for our own mesh engine and a render node, once it gets the reboot it has been waiting for. EdgeXpert stays with Siti and the twin brain; it only joins if a model needs more memory than 12 GB.
  4. Astra's jobAstra drives Blender: writes and repairs the clean-up scripts, decides how to retry a bad mesh. Claude builds the pipeline and acts as the second pair of eyes. Never the same model writing and judging, same rule as the Studio.
  5. DashboardA fourth lane in studio.neotodak.com called Objek, with the same five-gate shape. No new dashboard. The viewer page and the "send to Game Kit" button live there.
01

What the Cospace clothing attempt actually taught us

The June to August work is all on record. Reading it back, the picture is clearer than "the 3D was not accurate".

What happenedRoot causeDoes it apply to generic objects?
Garments stayed frozen or exploded on the avatarRig mismatch. The garments used one skeleton, the bodies another, zero shared bone names. An asset problem, not a code problem.No. A chair, a shoe or a lamp has no skeleton.
Sleeves did not follow the armsWeight transfer put sleeve vertices on the torso. Only arms-out (T-pose) garments auto-rig cleanly; arms-down sources are hard.No. Nothing to rig.
Garments looked tight, gappy, or like a pufferFit was scaled by height only, then patched with body-envelope scaling. Some engines inflate the shape.Partly. Size still matters, but the reference is now the product's own dimensions, not a body.
Skin and shirt patches baked into the textureSource photo had a person or busy background. The engine reproduces whatever is in the picture.Yes. Fixed by cleaning the image first and generating extra views.
First engine too coarseHiggsfield's mesh was rough. Switching to Tripo gave clean geometry and passed every check.Yes. Engine choice is a bake-off, not a guess.
No "generate" button ever shippedNo machine with Blender behind the Cospace server, and the Studio UI sits in Lan's repo.Yes, and this is the real fix. This plan puts Blender on a fleet worker with a queue in front of it.

By 23 July there was a one-command tool that turned a product image into a wearable top that passed the validator, on garments it had never seen. What was missing was a backend and a button. Clothing stays a separate, later lane that reuses that tool. This plan is for everything else.

02

The seven steps, and who runs each one

Every step writes its result to the job row in the Studio database and drops files in the media bucket, so the dashboard shows progress live and any step can be re-run alone.

  1. 0
    Intake Studio
    You give one of three things: an image, a link (Shopee, Lazada, any product page), or a sentence describing the object. The Studio creates a job in the Objek lane. Nothing costs money yet.
  2. 1
    Fetch and understand tr-home Astra
    For a link, the browser desk on tr-home opens the page with a real Chrome profile (Shopee blocks plain scrapers) and pulls the product photos, title, and the listed dimensions and weight. Astra writes a product card: what it is, category, real size in centimetres, materials, whether it is symmetric, which views we have. Pintu 0: you confirm the card, above all the size. This is the calibration, done before any money is spent.
  3. 2
    Reference set tr-home image model
    Cut the object out of its background. Generate the views we do not have (back, side, top) with an image model told to keep the same object. Result: two to four clean views on white. Pintu 1: a reviewer model checks the views agree with each other. About RM1 to 2.
  4. 3
    Mesh generation hosted engines
    Send the views to a hosted image-to-3D engine and get a textured mesh back. Version 1 uses Tripo through fal.ai because it already proved itself in July. The lane runs a second engine in parallel (Hunyuan3D, Meshy or Rodin) so you get two candidates, and the winner count becomes a leaderboard like the Studio's writer bake-offs. About RM3 to 8 per candidate.
  5. 4
    Blender clean-up and calibration tr-home Astra
    Blender runs headless from scripts, no window. Fix orientation (the July bugs are documented: quaternion rotation, the Y-up wrapper), scale to the real size from the product card, set the origin and floor, reduce polygons to the target (web or game), close holes, fix normals, remove stray pieces, bake a clean 2K texture, and export three files: GLB for the web and Godot, USDZ for iPhone AR, FBX for other engines. Then render a turntable: eight stills and a six-second spin on the 24 GB GPU. Automatic checks: bounding box within 5% of the card, watertight, polygon budget, texture size, no stray meshes. Astra's role: when a check fails, it edits the script or changes the parameters and re-runs, up to three tries.
  6. 5
    Second pair of eyes EdgeXpert or cloud
    Pintu 2: a vision model that is not Astra compares the turntable with the source photos and scores 0 to 10 with a list of issues: wrong proportions, smeared logo, missing part, fake back side. Below the bar, the lane goes back to step 3 with the other engine or a new seed. Above the bar, you see source and result side by side and press Lulus or Gagal.
  7. 6
    Publish and use Studio
    Files go to the media bucket. The Studio shows the object in a browser viewer you can spin, with an AR button on a phone. Buttons: copy share link, download, send to Game Kit (drops the GLB into a student's Godot project as a ready asset), and later, send to Cospace through the July garment tool for tops only.

Why this works where the clothing version stalled

  • No skeleton, no body, no fit tuning. The hardest 80% of the old problem is gone.
  • Size is confirmed by a person before generation and measured by a script after. That is the calibration, and it is checkable.
  • The engine reproduces what it sees, so we control what it sees: clean cut-out, extra views, no people, no clutter.
  • A judge that is not the maker looks at every result before you do.
  • A queue and a worker exist. The button finally has something behind it.

What it still cannot do well

  • The back of an object only ever shown from the front is invented. Extra views reduce this, they do not remove it.
  • Glass, chrome, thin wire and transparent parts come out wrong on every engine today.
  • Logos and printed text smear. A fix step can re-project the source photo onto the front face, but small text stays soft.
  • Shop links are best effort. Shopee changes its pages and blocks robots; when the fetch fails, you paste the images and carry on.

04

Where Astra fits, and where it should not

GPT-6 Astra is real, released 3 September, and OpenAI markets it as strong at Blender and 3D reasoning. We can use it today: Codex is logged in on your Mac and on tr-home, and the API key works.

Astra on tr-home, inside the pipeline (recommended)

  • Runs as a background command per job, no chat window: "here is the mesh, the product card and the failed check, fix it".
  • Writes and repairs the Blender scripts. The scripts, not the chat, are what runs next time.
  • Its output is judged by a different model. Same rule as the Studio writer and reviewer.
  • Swappable. If Claude or a newer model does the Blender step better in a bake-off, change one setting.

Astra in Codex on your Mac, by hand

  • Good for the first week: exploring what Astra can do in Blender, building the scripts.
  • Not a pipeline. Your Mac must not become the worker, and the browser control rule already says the same.
  • No queue, no gates, no record of what was tried.

Version 1 uses Astra for steps 1 and 4 and a Claude or Gemini vision model for step 5. Claude Code builds the worker and the Studio lane. The first bake-off is Astra against Claude on the same five broken meshes; whoever repairs more of them keeps the job.

Build list and cost

About one week of work. Estimates, not quotes.

  1. Blender and the worker on tr-home · 1 day. Official Blender, a worker process that polls the Objek queue, the fal.ai and image-model calls, the Codex runner.
  2. Clean-up scripts · 2 days. Orientation, real-size scaling, decimation, hole closing, texture bake, three exports, turntable render, the automatic checks. Astra and Claude both write against the same five test objects.
  3. Objek lane in the Studio · 1.5 days. Job table, three gates, viewer page, send-to-Game-Kit. Built with the Studio session that owns that repo.
  4. Judge and retry loop · 1 day. Vision scoring, the retry rules, the engine leaderboard.
  5. Dry run · 1 day. Five real Shopee items of different kinds: a shoe, a chair, a bottle, a toy, a lamp. Every snag goes into the scripts before anyone else uses it.

  4. 3Astra runs the Blender step from inside the pipeline on tr-home; a different model judges; Claude builds. First bake-off decides who keeps the Blender job.
