Its own home, off Neo's estate

Neo's note of 20 September: the program is shared with the Academy team, so it should not run on his personal domain (neotodak.com) or his personal machines (the office fleet, the NAS, the Bandung box). This page proposes a home that Todak Academy and Todak Studios own, names what moves, and prices it. Everything in the student's path lands on Academy or Studios accounts. Neo's fleet may lend a hand in the dry run and nowhere else.

Update, 20 Sep (later the same day). Neo decided the base stays course.neotodak.com. No domain move, no redirects. Everything else on this page, the accounts, the database, the server and the build farm being Todak-owned, still stands as proposed.

Short version
  1. DomainDecided 20 Sep: course.neotodak.com stays as the base. Site, documentation, slides and the showcase live there, as today. The classroom and the collector use paths or subdomains under it.
  2. OwnershipOne rule: every account in the chain belongs to a Todak entity, with Lan and Neo as owners and Kai as IT admin. No personal accounts, no personal tokens, no Siti, no neo-brain.
  3. HostingStatic site and showcase on the Todak Cloudflare account (free). Code in a new todak-academy GitHub organisation (free). Classroom system and course database in a Supabase project inside the Todak organisation, next to the Academy portal's. Collector and publisher desk on the Academy's own server in the Kay rack.
  4. MachinesThe Mac mini becomes an Academy asset, placed at the Academy, reached through a Cloudflare Tunnel on the Todak account, not Neo's private network. No Academy workload on EdgeXpert, tr-home, the NAS or bandung-01.
  5. AI servicesThe two seats do most of the work. Bulk images, 3D and sound go to rented GPU by the hour during class weeks and pay-per-use services through the kit, on Academy accounts with a per-student budget. An Academy GPU box is bought only if a second cohort proves the demand.
  6. CostAlmost nothing new: the hosting is free, the database is the same line as before, GPU rental is a few hundred ringgit per cohort. The one-off is the Mac mini, already approved.
01

Why this matters

  • Continuity. If the program lives on Neo's personal domain and machines, it lives only as long as Neo's personal setup does. Lan's team, the lecturers and Kai need a home they can run without Neo in the loop.
  • Access. Neo's fleet holds his personal agents, his WhatsApp lanes and his brain. Giving the Academy team access to it, or running student jobs next to it, mixes two worlds that should stay apart.
  • Credibility. A JPK-aligned course on an .edu.my address reads as the institution's course. The same course on a personal domain reads as a side project.
  • Data. Student prompt records, signed paperwork and grades belong to the Academy under its own data-protection consent, on the Academy's accounts.

Why Cloudflare and not Netlify. Todak already has the Cloudflare account that holds todak.com and todakstudios.com, so the site, the tunnel to the Mac mini, the file bucket and the access control all sit under one company login with no new vendor. Netlify would need a new team on a company card for the same result.

How the pieces reach each other

Student PC or laptopWorkbench pushes code to the todak-academy GitHub organisation. Prompt events go to the collector over HTTPS.
→
Kay .213 · Academy serverCollector, publisher desk, build queue, store watch, uptime. Public address, keys-only SSH, Cloudflare in front.
→
Mac mini · build farmPulls jobs from the queue over its Cloudflare Tunnel, builds every platform, uploads to the stores and to R2, posts the link back.
  • No private network to join. The student never needs a VPN. The Mac mini is reached only through its tunnel, with Cloudflare Access deciding who may open it (Lan, Neo, Kai, the academy-cc identity).
  • If a private network is wanted anyway for admin convenience, a small Tailscale network on an Academy plan is the alternative. The free personal plan now allows six users and unlimited devices, but it is meant for personal use, so the Academy should be on a paid starter seat per admin if it goes that way.
  • Nothing here touches Neo's tailnet, his agents or his brain. The one exception allowed: during the dry run, before cohort 1, Neo's tr-home may build the first reference game to save time. It is removed from the path before enrolment.

05

What moves, in what order

About one week of work once the accounts exist. Nothing on the current pages changes until the new home is live and checked.

  1. Accounts (Lan or Kai, one afternoon): the todak-academy GitHub organisation; the creator-classroom Supabase project in the Todak organisation; the Cloudflare Pages project, tunnel and R2 bucket on the Todak account; the todakcreator.com registration if wanted; the Academy password manager.
  2. Site and docs: nothing to move. Transfer the repository into the organisation and point the existing deploy at it.
  3. Classroom: export the current classroom database, import into creator-classroom, transfer the repository, keep it at classroom.neotodak.com, re-test login and grading.
  4. Kay .213: deploy the collector, the publisher desk, the build queue and the store watch as services; wire alerts.
  5. Mac mini: set up as the Academy asset with the tunnel and the Studios keychain, connect to the queue.
  6. Clean-up: remove the Academy's crons and watchers from Neo's fleet; Neo's fleet keeps nothing of the program.
