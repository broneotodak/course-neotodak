Two weeks to a working demo

Everything else on this site is a proposal. This page is a build. In two weeks a real beginner sits at a Todak Workbench, makes Pong with the two AI desks, publishes it to the web, and Lan watches the prompts land in the classroom system. Ten minutes, live. It doubles as the first dry-run item the plan already calls for, so nothing is wasted if the answer afterwards is "not yet".

Short version
  1. GoalA ten-minute live demo: open the Workbench, design with Astra, build with Claude Code, press Play in Godot, publish to the web, see the prompt journey, get the review report. Done means a beginner has done it, not us.
  2. ScopeWeb only. One game, Pong. One lab PC. The pieces of the kit that the demo touches, and nothing else.
  3. WhoClaude Code builds the backbone. Codex builds the sidebar and the Pong art. Claude Code directs and verifies. Neo picks the date and the beginner.
  4. CostNo new cash. The two seats we have, tr-home for web builds during this dry run only, and one Academy Windows PC on the day.
  5. LabelThe screen says "demonstrator, not the kit" the whole time, the way the animations say "animation, not a screenshot".

04

What could bite

  • The Codex desk on Windows. A reported case of the Astra model missing from the Windows app's picker. Checked on day 6; the fallback is the Codex panel in the editor or Codex in the browser.
  • Godot web builds need two headers on the hosting site. Set once on the showcase, tested on day 3.
  • Windows testing. The build happens on Mac and Linux; the first Windows run is day 6. If the lab PC is not available, Neo's Windows machine stands in.
  • Recording both desks. Claude Code's hooks are documented; Codex's session transcripts are collected from disk. If either fails on the day, the journey page shows what was captured and says so.
  • A demo looks like a product. It is not. The label stays on screen.
