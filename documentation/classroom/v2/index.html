01

The student's screen

What the student sees is one box. Two chat panels were the first design; Neo and Lan both saw the problem: a beginner with little AI knowledge would not know which one to type into. So the Workbench has a single Todak desk. Behind it, a small router sends each request to the right AI, the design desk (Astra, through Codex) for artwork, sound and design documents, the build desk (Claude Code) for code, builds, reviews and publishing, or to both in sequence when a request needs both. The box always says which desk it used and why, and the student can send a request to the other desk with one click. That line is itself a lesson in what each AI is for. The two tools' own panels stay installed and appear from week 4, so nobody graduates without having seen the real tools.

Animation, not a screenshot. The real Workbench is built in the kit phase.

One monitor works with a floating game window. Two 24-inch monitors are preferred. The projector shows the lecturer's Workbench for demos, then the class dashboard: steps, builds and showcase links. Personal prompt histories and assessment notes stay off it.

03

One box, two AIs behind it

Neo's own worry, and the answer: "build me a 3D Pong" and learn nothing. The box is where the course rules live. Two raw panels cannot enforce any rule; one box can.

Rule inside the boxWhat the student experiences
Routing, shown"Sent to the design desk (Astra), because you asked for artwork." Or "to the build desk (Claude Code), because you asked the paddle to move." A wrong guess is one click to fix, and the student learns what each AI is good at.
Step gating"Build me the whole game" gets: "Not in one go. You are on step 2, the paddle. Ask for that." Requests beyond the current step are done only as far as the step allows.
Explain it backAfter every code change, the next change stays locked until the student tells the desk in one sentence what the last change did. Those sentences feed the walkthroughs and the viva.
Prompt scoring"Do everything" prompts score low in the journey; specific, informed prompts score high. The lecturer sees the growth.
RecordingThe box records every request itself, with the route and the reason, so the journey no longer depends on hooks or transcript scraping.
One login is enoughA student with only a Claude login, or only a ChatGPT login, still works: everything routes to the desk they have. Both logins remain the plan.
Under the hoodFrom week 4 the raw Claude Code and Codex panels appear beside the box, and the no-AI debugging drills begin, as before.

Behind the box, the lanes are unchanged. Astra owns design: the design document, moodboards, character sheets, sprites, sounds, the title art, all as files in design/ and assets/. Claude Code owns the build: scaffolding, gameplay code with the student, project memory, builds, reviews, publishing, and merging Astra's work after tests. Work still crosses as files plus a short note. What changed is only what the student has to look at.

Where it runs. The box lives in the Todak sidebar and calls the kit's tgk ask command, which drives Claude Code and Codex on the student's own PC with their own logins. No server in the middle, no wrapper platform. The two tools' rich views are one click away.
